# Profile-page card behavior audit — 2026-07-19

Scope: the candidate profile at `GET /candidates/{id}`, its immediate edit,
file, parsing, and preference flows. This is a behavior audit, not an
implementation plan. It was performed by tracing the rendered templates,
client handlers, and their routes; it does not change application data.

## Contract and target pattern

R1 requires multiple uploaded files, per-file extraction, editable curated
titles and skills, and an eventual per-file inspection experience.
`docs/design/scoring-and-provenance.md` further defines curated values versus
per-document extraction occurrences. R2 is more immediate: every candidate
profile card (including future cards) must use the same fold/unfold, listing,
file-open, and edit affordances; a working but divergent card is a defect.

Use one shared profile-card pattern after the next implementation slice:

| Concern | Target behavior |
| --- | --- |
| Fold/unfold | Every information/collection card has the same keyboard-accessible header control, visible expanded/collapsed state, and initially-expanded policy. Header actions do not toggle the card. |
| Listing | Render active items before slicing. Use the same preview limit, an accurate count, and a toggle whose label and icon change between “Show N more” and “Show less”. Empty states retain the primary action. |
| Files | Every document row exposes an explicit Open/View action. Text preview, PDF open/download, extraction facts, errors, and destructive actions have consistent feedback; never leave the user at a terminal placeholder. |
| Edit | Card edit actions have an explicit entry point, draft/loading/error state, save/cancel semantics, and success feedback. Curated title/skill edits preserve provenance and offer reset-to-extracted once that slice lands. |

## Cross-card prioritized findings

1. **P0 — correct Documents active-list slicing/counting.** It produces missing or misleading visible data after a normal soft delete and breaks the shared listing contract.
2. **P0 — make Skills foldable.** This is a direct, immediately observable R2 violation.
3. **P0 — repair Search Preferences summary bindings.** The profile presently reports values that do not exist in the model, so saved user choices are misrepresented.
4. **P0 (design-required; sequence after T2 groundwork) — represent and expose curated-value provenance.** The current title bulk save copies only a single source-document reference and cannot represent R1’s extracted-vs-edited/per-file contract. The future occurrence-table slice is the correct home; the shared-card slice must not create a competing provenance model.
5. **P1 — unify Documents row rendering and give PDFs a real open/download action.** The first-three and overflow menus are already behaviorally different.
6. **P1 — make title and skill parse/edit flows a single interaction family.** The two curated collections use incompatible modal, review, and editing models despite R2.
7. **P2 — standardize reversible “show more/show less” controls, preview limits, empty states, and truthful feature copy.** This is low-risk once the shared card/list components exist.
